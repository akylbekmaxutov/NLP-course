Бүкіл pipeline бір функцияда

Жоғарыдағының бәрі жазылған түрі. Іске қосыңыз — кестедегі дәл сол вектор, сол тоғыз сан шығады.

import re
from collections import Counter

VOCAB = ['алматыда', 'астанада', 'ауа', 'бүгін', 'емес',
         'жауды', 'жақсы', 'жаңбыр', 'райы']

def pipeline(text):
    text = text.lower()
    text = re.sub(r"[^\w\s]", " ", text)
    return text.split()

raw = "  Астанада ауа райы ЖАҚСЫ!!!  "
tokens = pipeline(raw)
counts = Counter(tokens)

print("tokens:", tokens)
print("vector:", [counts[w] for w in VOCAB])
tokens: ['астанада', 'ауа', 'райы', 'жақсы']
vector: [0, 1, 1, 0, 0, 0, 1, 0, 1]

Соңғы жолды оқыңыз: вектор бекітілген сөздікке қарсы құрылады, сондықтан 2-орын әрқашан астанада, 7-орын әрқашан жақсы дегенді білдіреді. Сөздікті өзгертсеңіз, сақталған векторлардың бәрі мағынасын жоғалтады — сондықтан векторизаторды модельмен бірге сақтау керек.

Теория · 1-қадам

Нормализация — мәтінді салыстыруға жарамды ету

Нормализация мағынасы бірдей мәтінді бірдей жазба түріне келтіреді, сонда жолдарды салыстыратын компьютер оларды тең деп көреді.

Регистр

Астана мен АСТАНА — кіші әріпке келтірмейінше әртүрлі жолдар.

Бос орындар

Tab, қос бос орын және жол ауысулары бір бос орынға жиылады — 1-дәрістегі \s+ үлгісі.

Тыныс белгілері

Unicode

Бір әріп екі түрлі сақталуы мүмкін; NFC нормализациясы оларды байт деңгейінде теңестіреді.

Қазақ тілі қосымша мұқияттылықты талап етеді

Біздің мәтіндерге тән тұзақтар
  • Екі жазу жүйесі. Бір сөз кириллицада (Астана) да, латында (Astana) да келуі мүмкін. Векторизатор үшін бұл — байланысы жоқ екі термин.
  • Ұқсас әріптер. Кириллицадағы А, В, С, Е, О, Р латынның A, B, C, E, O, P әріптерімен көзге бірдей, бірақ кодтары бөлек — автокөлік нөмірлерінде көрген мәселенің дәл өзі.
  • Тек қазақ тіліне тән әріптер. ә ғ қ ң ө ұ ү һ і әріптерін қазақ пернетақтасы жоқ адамдар кейде а г к н о у у х и деп теруі мүмкін.
  • і әрпі. Қазақтың і (U+0456) әрпі мен латынның i әрпі көптеген қаріпте бірдей көрінеді және нақты деректерде үнемі шатастырылады.

Мұның бірі де сирек жағдай емес — қазақстандық мәтін деректері дәл осылай көрінеді, сондықтан нормализация ешқашан «жай ғана .lower()» болмайды.

Тазалау жоятын нәрсені қалай сақтап қалуға болады

Жоғарыдағы мәселенің шешімі: белгілерді тазалауға дейін бөліп алыңыз, ал hashtag-ты токенизация жұтып қоймайтындай етіп қайта жазыңыз.

import re

raw = "Сәлем, ӘЛЕМ!!! Бүгін #NLP сабағы бар."

# 1. save the signals BEFORE cleaning destroys them
features = {
    "exclamations": raw.count("!"),
    "hashtags": re.findall(r"#\w+", raw),
    "has_shouting": bool(re.search(r"\b[А-ЯЁӘҒҚҢӨҰҮҺІA-Z]{3,}\b", raw)),
}

# 2. keep the hashtag as one token instead of losing the #
protected = re.sub(r"#(\w+)", r"hashtag_\1", raw)
tokens = re.sub(r"[^\w\s]", " ", protected.lower()).split()

print(features)
print(tokens)
{'exclamations': 3, 'hashtags': ['#NLP'], 'has_shouting': True}
['сәлем', 'әлем', 'бүгін', 'hashtag_nlp', 'сабағы', 'бар']

Есте сақтайтын үлгі: алдымен шығарып ал, сосын тазала. exclamations және has_shouting сөз санақтарының қасындағы кәдімгі сандық белгіге айналады, ал hashtag_nlp жеке token болып сақталады — жіктеуіш оны nlp сөзінен бөлек үйрене алады.

Аралас жазуды қалай түзетуге болады

Кириллица мен латын тұзақтарының шешімі: NFC-ке келтіріп, ұқсас латын әріптерін кириллица егіздеріне ауыстырыңыз.

import unicodedata

# Latin letters that look identical to Cyrillic ones, both cases
LOOKALIKE = str.maketrans({
    "A": "А", "B": "В", "C": "С", "E": "Е", "H": "Н", "I": "І",
    "K": "К", "M": "М", "O": "О", "P": "Р", "T": "Т", "X": "Х",
    "a": "а", "c": "с", "e": "е", "i": "і", "o": "о", "p": "р",
    "x": "х", "y": "у",
})

def fix_script(text):
    return unicodedata.normalize("NFC", text).translate(LOOKALIKE)

cyrillic = "Астана"
mixed = "A" + "стана"          # the first letter is Latin A

print(cyrillic == mixed)
print(fix_script(mixed) == cyrillic)
print(fix_script("Ipi"), fix_script("Ipi") == "Ірі")
False
True
Ірі True

Көзге бірдей екі жол тең емес — мұны істемейінше. Бірінші print False береді. Бұл қадамды сөздерді санаудан бұрын, ерте орындаңыз, әйтпесе бір қала матрицаңызда екі баған алып тұрады. Кестені тек кириллицадағы мәтінге қолданыңыз: нағыз ағылшын сөздерін бүлдіріп жіберер еді.

Теория · 2-қадам

Tokenization — мәтінді бөліктерге кесу

Бір сөйлем, үш токенизатор. Әр жол жоғарғысы жоғалтқан нәрсені сақтайды, ал үшіншісі біреу баға мен бөлме санын маңызды деп шешкендіктен ғана бар.

Tokenization мәтінді token-дерге бөледі — модель санайтын ең кіші бірліктерге. Token әдетте сөз болады, бірақ міндетті түрде емес.

1-әрекет — бос орын бойынша бөлу

Ең қарапайым токенизатор 
text = "Сәлем, әлем! Бүгін NLP сабағы бар."
print(text.split())
['Сәлем,', 'әлем!', 'Бүгін', 'NLP', 'сабағы', 'бар.']

Мәселе бірден көрініп тұр: Сәлем, мен Сәлем енді екі бөлек token, бар. мен бар да солай. Сөздік ешбір себепсіз екі есе өседі.

2-әрекет — regex токенизаторы

Тек сөздер 
import re

text = "Сәлем, meeting сағат 15:00-де болады, Teams-ке кіресің бе?"
print(re.findall(r"\w+", text))
['Сәлем', 'meeting', 'сағат', '15', '00', 'де', 'болады', 'Teams', 'ке', 'кіресің', 'бе']

Жақсырақ — бірақ мұқият қараңыз. 15:00 уақыты 15 және 00 болып бөлінді; Teams-ке сөзі Teams және ке жалғауына жарылды. Екеуі де анық қате емес: бәрі тапсырмаңыз уақыттарға және ағылшын сөздеріне жалғанған қазақ жалғауларына мән бере ме, соған байланысты.

«Дұрыс» токенизатор деген жоқ. Тек тапсырмаға сай келетін токенизатор бар. Егер сізге уақыт пен телефон нөмірі керек болса, оларды сөзге бөлмес бұрын 1-дәрістегі Regex үлгілерімен қорғап алыңыз.

Сөйлемге бөлу

Сөйлемдерге бөлу — бөлек тапсырма, ал «әр нүктеде бөлу» деген қарапайым тәсіл қысқартулар мен бас әріптерде қателеседі: А. Құнанбайұлы — екі сөйлем емес. Оның мұқият нұсқасын 1-дәрісте lookbehind арқылы кездестірдік.

Бөлінбеуі керек нәрсені қалай қорғауға болады

15:00 мәселесінің жауабы: алдымен құрылымды бөліктерді 1-дәрістегі Regex үлгілерімен орынбасарға ауыстырыңыз, тек содан кейін сөзге бөліңіз.

import re

def protect(text):
    text = re.sub(r"\+7(?:[\s-]?\d){10}", " <PHONE> ", text)
    text = re.sub(r"\b\d{2}\.\d{2}\.\d{4}\b", " <DATE> ", text)
    text = re.sub(r"\b\d{1,2}:\d{2}\b", " <TIME> ", text)
    text = re.sub(r"#(\w+)", r" hashtag_\1 ", text)
    return re.sub(r"\s+", " ", text).strip()

raw = "Сәлем, meeting 15:00-де, 24.08.2026 күні. Тел: +7 701 123 45 67 #NLP"

print(protect(raw))
print(re.findall(r"<\w+>|\w+", protect(raw)))
Сәлем, meeting <TIME> -де, <DATE> күні. Тел: <PHONE> hashtag_NLP
['Сәлем', 'meeting', '<TIME>', 'де', '<DATE>', 'күні', 'Тел', '<PHONE>', 'hashtag_NLP']

Бір мезгілде екі ұтыс. Уақыт, күн және телефон нөмірі цифрларға жарылмай, бір token болып сақталады, әрі телефон нөмірі жол-жөнекей жасырылады — бір жол әрі белгі жасайды, әрі құпиялықты қорғайды. Оның үстіне орынбасарлар сөздікті кішірейтеді: корпустағы әр телефон нөмірі мыңдаған емес, бір баған болады.

Дефиспен жазылған есімдерді қалай бүтін қалдыруға болады

Бір токенизатор, ретімен үш ереже: дефиспен жазылған кириллица есімі, содан кейін кез келген жазудағы жай сөз, содан кейін сандар.

import re

KAZ = "А-ЯЁӘҒҚҢӨҰҮҺІа-яёәғқңөұүһі"
TOKEN = re.compile(rf"[{KAZ}]+(?:-[{KAZ}]+)+|[{KAZ}]+|[A-Za-z]+|\d+")

text = "Қасым-Жомарт Тоқаев Teams-ке кірді"
print(TOKEN.findall(text))
['Қасым-Жомарт', 'Тоқаев', 'Teams', 'ке', 'кірді']

Қасым-Жомарт бір token болып қалады, себебі бірінші балама бірінші сыналады, ал Teams-ке бәрібір бөлінеді — ондағы дефис екі түрлі жазуды жалғап тұр, ал бұл — біз бөлгіміз келетін жағдай. Барлық қулық баламалардың ретінде: ең ұзын, ең нақты ережені бірінші қойыңыз.

Бас әріптерге бөлінбей, сөйлемге қалай бөлуге болады

Қарапайым бөлгіш А. дегеннен кейін кесіп жібереді. Қорғаныш бір әріптік бас әріптің нүктесін жасырып, бөлгеннен кейін орнына қайтарады.

import re

text = "Абай А. Құнанбайұлы — ақын. Ол 1845 жылы туған! Солай ма?"

naive = re.split(r"(?<=[.!?])\s+", text)
print("naive   :", naive)

guarded = re.sub(r"\b([А-ЯЁӘҒҚҢӨҰҮҺІ])\.\s", r"\1<DOT> ", text)
parts = [p.replace("<DOT>", ".") for p in re.split(r"(?<=[.!?])\s+", guarded)]
print("guarded :", parts)

Subword token-дер — заманауи модельдер сөзді неге бөледі

Қазақ тілінде ағылшын тілінде жоқ мәселе бар: бір түбір орасан көп тұлға береді, сондықтан сөз деңгейіндегі сөздік өсуін тоқтатпайды.

Бір түбір — көп жазба

Сөз деңгейіндегі сөздік үшін бұлар — байланысы жоқ бес термин:

  • кітап
  • кітаптар
  • кітаптарым
  • кітапхана
  • кітаптарымыздан

Мұны тілдегі әр зат есімге көбейтіңіз — сөздік жарылады. Оның үстіне модель оқыту кезінде көрмеген тұлға оған мүлде беймәлім болады — бұл out-of-vocabulary мәселесі.

Заманауи жауап — token-дерді сөзден кіші ету. Subword токенизаторы деректерден жиі кездесетін таңба тізбектерін үйреніп, сирек сөздерді таныс бөліктерге бөледі:

  • кітаптарымыздан →
  • кітап +
  • тар +
  • ымыз +
  • дан
Бұл — иллюстрация, нақты модельдің шығысы емес. Нақты бөліктер токенизатор қандай корпуста оқытылғанына байланысты. Маңыздысы — бұрын кездеспеген сөзді де бейнелеуге болады, себебі оның бөліктері таныс. BPE (GPT модельдерінде) және WordPiece (BERT-те) — сіз Transformers дәрістерінде қайта кездестіретін екі алгоритм.

Бүгінге сөз деңгейіндегі token-дермен қаламыз: Bag of Words-қа дәл солар керек әрі оларды көзбен тексеру оңай.

BPE жиырма жолда

Бұл нағыз токенизатор емес, бірақ нағыз алгоритм: жеке таңбалардан бастап, ең жиі кездесетін көрші жұпты қайта-қайта біріктіру.

from collections import Counter

words = ["кітап", "кітаптар", "кітаптарым", "кітаптарымыздан"]
corpus = {" ".join(word) + " </w>": 1 for word in words}

def best_pair(corpus):
    pairs = Counter()
    for word, freq in corpus.items():
        symbols = word.split()
        for i in range(len(symbols) - 1):
            pairs[symbols[i], symbols[i + 1]] += freq
    return pairs.most_common(1)[0]

for step in range(1, 5):
    (left, right), count = best_pair(corpus)
    corpus = {w.replace(f"{left} {right}", left + right): f
              for w, f in corpus.items()}
    print(f"merge {step}: {left!r} + {right!r}  (seen {count}x)")

print(list(corpus)[-1])

Шынымен жұмыс істейтін жалғау кескіш

SUFFIXES = ["ымыздан", "імізден", "ларымыз", "леріміз", "тарымыз",
            "дан", "ден", "тан", "тен", "нан", "нен",
            "лар", "лер", "тар", "тер", "дар", "дер",
            "ым", "ім", "ың", "ің", "да", "де", "та", "те"]

def strip_suffixes(word, min_stem=4):
    changed = True
    while changed:
        changed = False
        for suffix in sorted(SUFFIXES, key=len, reverse=True):
            if word.endswith(suffix) and len(word) - len(suffix) >= min_stem:
                word = word[: -len(suffix)]
                changed = True
                break
    return word

Теория · 5-қадам

Bag of Words — алғашқы вектор

Құжатқа бір жол, сөздік сөзіне бір баған. 2 және 3-жолдар байтпен бірдей — курс осы кемшілікті түзетуге тағы үш дәріс жұмсайды.

Bag of Words құжатты оның сөздерінің саны ретінде бейнелейді. Жинақтағы барлық терминнен сөздік құрасыз, содан кейін әр құжат сандар қатарына айналады — әр терминге бір баған. Сөз тәртібі алынып тасталады; сондықтан бұл «қап» (bag).

Толық мысал — үш сөйлем

D1: Астанада ауа райы жақсы
D2: Алматыда ауа райы жақсы емес
D3: Астанада бүгін жаңбыр жауды

1-қадам — токенизациялау және кіші әріпке келтіру:

D2: ['алматыда', 'ауа', 'райы', 'жақсы', 'емес']

['алматыда', 'астанада', 'ауа', 'бүгін', 'емес', 'жауды', 'жақсы', 'жаңбыр', 'райы']

3-қадам — санау:

Осы кесте — бүкіл идея. Үш сөйлем енді үш вектор, ал модель жолдарды салыстыру арқылы олардың қаншалық ұқсас екенін өлшей алады.

D1 мен D2-ге қараңыз. Олар дәл екі орында ғана өзгеше — алматыда және емес — бірақ бірі ауа райы жақсы десе, екіншісі жақсы емес дейді. Bag of Words емес сөзінің сөйлемді болымсызға айналдыратынын білмейді, себебі ол сөздің қай сөздің қасында тұрғанын ешқашан көрмейді. N-грамдарға жеткенде осыны есте сақтаңыз.

Екі вектордың ұқсастығын өлшеу

Модель сол жолдармен шын мәнінде осыны істейді — cosine similarity, яғни екі құжат арасындағы бұрыш.

import re, math
from collections import Counter

docs = ["Астанада ауа райы жақсы",
        "Алматыда ауа райы жақсы емес",
        "Астанада бүгін жаңбыр жауды"]

tokens = [re.findall(r"\w+", d.lower()) for d in docs]
vocab = sorted({w for t in tokens for w in t})
vectors = [[Counter(t)[w] for w in vocab] for t in tokens]

def cosine(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    return dot / (math.sqrt(sum(x * x for x in a)) * math.sqrt(sum(y * y for y in b)))

print("D1 vs D2:", round(cosine(vectors[0], vectors[1]), 3))
print("D1 vs D3:", round(cosine(vectors[0], vectors[2]), 3))

D1 vs D3: 0.25

D1 мен D2 67% ұқсас болып шықты, бірі ауа райы жақсы десе, екіншісі жақсы емес десе де; ал екеуі де Астана туралы D1 мен D3 небәрі 0.25 алады. Bag of Words ортақ мағынаны емес, ортақ сөздікті өлшейді. Биграмдарды қосқанда осы санды есте ұстаңыз.

Теория · 6-қадам

TF-IDF — сөздердің бәрі бірдей пайдалы емес

Жолақтар әр сөз неше құжатта бар екенін көрсетеді. IDF соған кері: барлық құжаттағы сөз ештеңе ажыратпайды, сондықтан оның салмағы құлайды.

Жай санауда әр құжатта кездесетін сөз бір ғана құжатта кездесетін сөзбен бірдей салмақ алады. Бірақ құжатты ерекше ететін — сирек сөз.

TF-IDF терминнің осы құжатта қаншалық жиі кездесетінін оның барлық құжаттар бойынша қаншалық сирек екеніне көбейтеді.

TF — термин жиілігі

Термин осы құжатта неше рет кездеседі, әдетте құжат ұзындығына бөлінеді: tf = саны / жалпы token саны

IDF — кері құжат жиілігі

Термин жинақта қаншалық сирек: idf = ln(N / df), мұндағы df — терминді қамтитын құжат саны.

Әр термин бір реттен кездеседі, сондықтан жай Bag of Words бәріне бірдей салмақ берер еді. TF-IDF болса, осы сөйлемді шынымен ерекшелейтін екі сөз — алматыда мен емес — үш есеге жуық маңыздырақ дейді.

Әр құжатта кездесетін сөздің idf мәні ln(1) = 0 болады — оның салмағы дәл нөлге айналады. TF-IDF стоп-сөздер тізімінің жұмысын үнсіз атқарады, оның үстіне ол біреудің тізімінен емес, өз деректеріңізден үйренілген.

Әр құжатты қай сөздер ұстап тұр

Әр терминді TF-IDF салмағы бойынша реттеу векторизатордың әр құжат не туралы деп ойлайтынын көрсетеді.

import re, math
from collections import Counter

docs = ["Астанада ауа райы жақсы",
        "Алматыда ауа райы жақсы емес",
        "Астанада бүгін жаңбыр жауды"]

tokens = [re.findall(r"\w+", d.lower()) for d in docs]
vocab = sorted({w for t in tokens for w in t})
N = len(docs)

df = {w: sum(1 for t in tokens if w in t) for w in vocab}
idf = {w: math.log(N / df[w]) for w in vocab}

for i, t in enumerate(tokens, 1):
    counts = Counter(t)
    scores = {w: counts[w] / len(t) * idf[w] for w in set(t)}
    top = sorted(scores.items(), key=lambda kv: (-kv[1], kv[0]))[:2]
    print(f"D{i} top terms:", [(w, round(s, 3)) for w, s in top])
D1 top terms: [('астанада', 0.101), ('ауа', 0.101)]
D2 top terms: [('алматыда', 0.22), ('емес', 0.22)]
D3 top terms: [('бүгін', 0.275), ('жауды', 0.275)]

D2-ні алматыда мен емес сипаттайды — дәл оны ерекшелейтін екі сөз. Сұрыптау кілті жай -score емес, (-score, term): мұнда бірнеше термин тең түсіп тұр, ал тең түскенді ажырататын кілт болмаса, шығыс реті әр іске қосқанда өзгерер еді.

N-грамдар — тәртіпті аздап қайтару

Биграмдар жақсы емес тіркесін бір белгі етіп ұстайды, сондықтан болымсыздық аман қалады — әлдеқайда кең сөздік бағасына.

N-грам — қатар тұрған n token тізбегі. Жеке сөздердің орнына (немесе олармен қатар) биграмдарды (n = 2) санау модельге кішкене контекст терезесін береді.

Оның бағасы. Сөздік тез өседі: 50 000 бөлек сөзі бар корпуста 2,5 миллиардқа дейін мүмкін биграм болады. Практикада тек жеткілікті жиі кездесетін биграмдарды қалдырасыз — scikit-learn-дегі min_df — және ұзағырақ байланыстар («жақсы деп айтуға болмайды») тізбекті оқитын модельдер шыққанша қолжетімсіз болып қалады.

Тек өз орнын ақтайтын биграмдарды қалдыру

Бұл — қолмен жасалған min_df: әр биграм неше құжатта кездесетінін санап, кемінде екі рет кездескендерін қалдыру.

import re
from collections import Counter

docs = ["ауа райы жақсы емес",
        "бүгін ауа райы жақсы",
        "ертең ауа райы жақсы болады"]

def bigrams(tokens):
    return [" ".join(pair) for pair in zip(tokens, tokens[1:])]

tokens = [re.findall(r"\w+", d.lower()) for d in docs]
doc_freq = Counter()
for t in tokens:
    doc_freq.update(set(bigrams(t)))

kept = sorted(b for b, n in doc_freq.items() if n >= 2)
dropped = sorted(b for b, n in doc_freq.items() if n < 2)

print("all bigrams :", len(doc_freq))
print("min_df >= 2 :", kept)
print("dropped     :", dropped)
all bigrams : 6
min_df >= 2 : ['ауа райы', 'райы жақсы']
dropped     : ['бүгін ауа', 'ертең ауа', 'жақсы болады', 'жақсы емес']

Алты биграм екеу болды. Не жоғалғанына назар аударыңыз: жақсы емес мұнда бір ғана құжатта бар, сондықтан қатаң min_df биграмдарды енгізу себебіміз болған дәл сол белгіні алып тастайды. Шағын корпуста min_df=1 қалдырыңыз; бұл шек — сапа емес, көлем туралы шешім.

Себебі жалғаулардың ұзындығы әртүрлі әрі үндестік заңымен тұлғасы өзгереді. Ереже кітап сөзін бүлдіреді (→ кі), ал кітаптарымыздан сөзіне әрең тиеді — бір түбір төрт бөлек белгіге айналады.

3-сұрақ

D1: ауа райы жақсы D2: ауа райы жақсы емес Bag of Words бұларды неге дұрыс ажырата алмайды және оны не түзетеді?

Жауапты көрсету

Векторлар бір ғана санға өзгеше, себебі сөз тәртібі мен көршілік жоғалған — емес тек тағы бір баған. Мұны биграмдар түзетеді: жақсы емес жіктеуіш бөлек үйрене алатын бір белгіге айналады.

4-сұрақ

Термин үш құжаттың бәрінде кездеседі. Оның idf мәні қандай және бұл нені білдіреді?

Жауапты көрсету

ln(3/3) = ln(1) = 0, сондықтан оның TF-IDF салмағы әр құжатта нөл. Барлық жерде кездесетін сөз ештеңені ажыратпайды — TF-IDF оны ешқандай стоп-сөздер тізімінсіз автоматты түрде алып тастайды.

5-сұрақ

Сіз қазақ тіліндегі клиент пікірлеріне арналған sentiment analysis жасап жатырсыз. Pipeline-дың қай қадамдарын өткізіп жібересіз және неге?

Жауапты көрсету

Стоп-сөздерді қалдырыңыз — әсіресе болымсыздықты білдіретін емес сөзін. Тыныс белгілерін, кемінде леп белгілерін, эмоция белгісі ретінде қалдырыңыз. Биграмдар қосыңыз. Кіші әріпке келтіру әдетте қауіпсіз, дегенмен БАС ӘРІППЕН жазу да белгі — оны бөлек белгі ретінде сақтауға болады.

Дәрістен кейін

Практикалық тапсырмалар

Бұларды өз бетіңізше орындаңыз. Жоғарыдағы зертхананы және Python файлын пайдаланыңыз — көбі он жолдан аспайды.

1-тапсырма — Нормализация

Кіші әріпке келтіретін, тыныс белгілерін алып тастайтын және бос орындарды жинайтын normalize() жазып, оны мынаған қолданыңыз: " АЛМАТЫ — Қазақстанның ең ІРІ қаласы!!! "

Жауапты көрсету

1-мысалдағы функция 'алматы қазақстанның ең ірі қаласы' береді. Сызықша да тыныс белгісі екенін ескеріңіз: ол бос орынға айналып, содан кейін \s+ арқылы жоғалады.

2-тапсырма — Сөздікті санаңыз

Мына екі құжатта барлығы неше бөлек термин бар? D1: ауа райы жақсы D2: ауа райы нашар

Жауапты көрсету

Төртеу. Сұрыпталған сөздік — ['ауа', 'жақсы', 'нашар', 'райы'], сондықтан D1 = [1, 1, 0, 1], D2 = [1, 0, 1, 1] — екі сөз ортақ, әрқайсысында біреуден өзгеше.

3-тапсырма — Телефон нөмірін қорғаңыз

Телефон нөмірі бір token болып қалатындай етіп токенизациялаңыз: "Хабарласыңыз: +7 701 123 45 67"

Жауапты көрсету

Токенизацияға дейін ауыстырыңыз: re.sub(r"\+7[\s\d]+", "<PHONE>", text), содан кейін сөзге бөліңіз. Орынбасар бір белгі болып сақталады, ал цифрлар сөздікті ластауын қояды.

4-тапсырма — Стоп-сөздер тізімін «бұзыңыз»

Стоп-сөзді алып тастағанда мағынасы төңкерілетін қазақша сөйлем табыңыз. Бұл қай тапсырманы бұзатынын түсіндіріңіз.

Жауапты көрсету

Кез келген болымсыздық: тамақ дәмді емес → тамақ дәмді. Бұл Sentiment Analysis-ті, пікірлерді жіктеуді және шағымдарды бағыттауды — таңба полярлыққа тәуелді әр тапсырманы — бұзады.

5-тапсырма — idf-ті қолмен есептеу

Жинақта 100 құжат бар. Термин олардың 10-ында кездеседі. ln(N/df) бойынша оның idf мәні қандай?

Жауапты көрсету

ln(100/10) = ln(10) ≈ 2.303. Ал 50 құжатта кездесетін термин ln(2) ≈ 0.693 береді — үш еседен астам аз салмақ.

6-тапсырма — Биграмдар

Мынаның барлық биграмын жасаңыз: "Астанада бүгін жаңбыр жауды"

Жауапты көрсету

['астанада бүгін', 'бүгін жаңбыр', 'жаңбыр жауды'] — төрт token-нен үш биграм. Жалпы ережесі: n token n − 1 биграм береді.

7-тапсырма — Қолмен лемматизациялау

Әр тұлғаның леммасын беріңіз және қандай жалғауларды алып тастағаныңызды айтыңыз: қалалар · қаладан · қалаларымызда

Жауапты көрсету

Үшеуі де қала түбіріне келеді. -лар көптік, -дан шығыс септік, -лар + -ымыз тәуелдік + -да жатыс септік.

8-тапсырма — Екі векторизаторды салыстырыңыз

Дәл сол үш ауа райы сөйлеміне CountVectorizer мен TfidfVectorizer қолданыңыз. D2-де қай термин ең үлкен салмақ алады және неге?

Жауапты көрсету

Санаумен әр термин 1-ге тең. TF-IDF-пен алматыда мен емес жеңеді, себебі олар үш құжаттың біреуінде ғана кездеседі, демек idf мәні ең жоғары.

9-тапсырма — Сөздіктің жарылуы

Зертханада «Бір түбір, көп тұлға» жиынын жүктеңіз. Неше баған шығады және идеалда нешеу болуы керек еді?

Жауапты көрсету

Төрт баған — кітап, кітаптарды, кітаптарымыздан, оқыдым — ал лемматизацияланған pipeline екеу берер еді: кітап және оқы. Агглютинативті тілде Lemmatization-ды өткізіп жіберудің бағасы осы.

10-тапсырма — Pipeline жобалаңыз

eGov сұрақтарын тақырып бойынша жіктеуге арналған pipeline жобалаңыз. Әр қадамды атап, әрқайсысын бір сөйлеммен негіздеңіз.

Жауапты көрсету

Дәлелді жауап: телефон нөмірлері мен ЖСН тәрізді цифрларды орынбасармен ауыстыру (құпиялық, әрі олар тақырып туралы ештеңе айтпайды); кіші әріпке келтіру; тыныс белгілерін алу; стоп-сөздерді алу (тақырып, сентимент емес); қазақ талдағышы болса — лемматизациялау; матрицаны кіші ұстау үшін ngram_range=(1, 2) және min_df=2 параметрлерімен TF-IDF.

Өзін-өзі тексеру тесті

Бірден кері байланыс беретін он сұрақ.

  1. Token дегеніміз не?

    Token — сіз санауды шешкен кез келген бірлік. Бүгін сөз деңгейінде, Transformer дәрістерінде subword.

  2. text.split() неге нашар токенизатор?

    Ол тек бос орын бойынша бөледі, сондықтан әр тыныс белгісі сөздікке жаңа жазба қосады.

  3. Қай жұп стеммингті емес, Lemmatization-ды көрсетеді?

    Lemmatization нағыз сөздік тұлғасын қайтарады. Қалғандары — сөз емес қалдық қалдыратын қиындылар.

  4. Bag of Words нені алып тастайды?

    Сандар сақталады, тәртіп сақталмайды — сондықтан болымсыздық оған көрінбейді.

  5. Үш құжат, термин үшеуінде де кездеседі. ln(N/df) бойынша idf мәні…

    ln(3/3) = ln(1) = 0. Барлық жерде кездесетін термин нөл салмақ алады.

  6. 3 құжаттан тұратын жинақта қай терминнің idf мәні ең жоғары?

    Термин неғұрлым сирек болса, idf соғұрлым жоғары: ln(3/1) = 1.099, ал ln(3/2) = 0.405.

  7. Қазақ мәтінінен емес сөзін алып тастау неге қауіпті?

    жақсы емес → жақсы: сентимент таңбасы керісінше ауысады.

  8. Төрт token неше биграм береді?

    n token n − 1 биграм береді — соңғысынан басқа әр token келесісімен жұптасады.

  9. Заманауи модельдер subword token-дерді неге қолданады?

    Әсіресе агглютинативті тілдерде құнды, себебі онда сөз деңгейіндегі сөздік шексіз өседі.

  10. TF-IDF қай шектеуді шешпейді?

    дәрігер мен емші бөлек баған болып қала береді. Мағынаны тек Word Embeddings байланыстырады — курстағы келесі қадам.
