AI Agents

9-дәрісте біз модельге құжат бердік, ол жауап берді. Мұнда біз оған құралдар жинағын беріп, олармен не істеу керегін өзі шешуіне жол береміз. Осы жалғыз өзгеріс — модель біздің pipeline-ды орындаудың орнына келесі әрекетті өзі таңдауы — адамдар agent деп атайтынның бәрі. Онымен бірге жаңа түрдегі баг пен жаңа түрдегі шот келеді.

Оқу мақсаттары

Осы дәрістің соңында сіз…

Agent дегеннің не екенін айта аласыз

Одан да пайдалысы — оның не емес екенін: ішінде модель тұрған тұрақты pipeline қанша қадамнан тұрса да agent емес.

Циклді жаза аласыз

Жиырма жол, фреймворксіз. Сұра, tool calls бар ма деп тексер, оларды орында, нәтижелерін қос, қайта сұра.

Tool жобалай аласыз

Функция, JSON схемасы және оны қашан қолдану керегін айтатын сөйлем. Сол сөйлем — prompt, және дәл ол agent жұмыс істей ме, жоқ па, соны шешеді.

Trace оқи аласыз

Нашар пайымдаған модельді істен шыққан құралдан ажыратып, екеуінің қайсысын жөндеу керегін білесіз.

Шотты болжай аласыз

Әр қадам бүкіл тарихты қайта жібереді. Жеті қадам неге екі қадамнан үш жарым емес, бес есе қымбат екенін білесіз.

Оған қоршау қоя аласыз

Қадам шегі, аргументтерді тексеру, қателер дерек ретінде және ешқашан eval жоқ. Agent — сіздің ақшаңызды жұмсайтын цикл.

Бұл беттегі әр trace нақты. code_files/lesson10/ ішіндегі agent 2026 жылғы 24 қыркүйекте gpt-4o-mini үстінде іске қосылды, ал қадамдар, tokens сандары мен уақыттар сол жүгірістерден тікелей көшірілген — оның ішінде қателескендері де.

Теория · Идея

Pipeline ма, agent пе?

9-дәрістегі RAG жүйесінде төрт қадам болды, және олардың бірде-бірі шешім емес еді. Сұрақты векторлау, бес үзінді алу, prompt құрастыру, генерациялау. Әр сұрақ дәл сол жолмен жүрді, өйткені сол жолды біз жаздық.

Agent — тілдік модель әрекет таңдап, нәтижесін көріп, бітті деп шешкенше қайта таңдай беретін цикл. Әрекеттер tools деп аталады: сіз оған ашатын кәдімгі функциялар.

Бұл нені береді және әрқайсысы неге тұрады
ол әрекет ете алады
Модель өздігінен мәтін шығарады. Құралдары бар модель болжамды қарай алады, ақша айырбастай алады немесе хат жібере алады. Бағасы — енді ол дұрыс емес нәрсе айтып қана қоймай, дұрыс емес нәрсе істей алады.
ол қадам санын бейімдейді
Оңай сұраққа бір шақыру, қолайсызына жеті. Мұнда өлшенген: сол agent бір сұраққа құралсыз жауап берді, екіншісіне жеті шақыру жұмсады. Бағасы — шотты сұраққа қарап болжай алмайсыз.
ол қалпына келеді
Tool қате қайтарғанда ол басқаша көруі мүмкін — және төмендегі жүгірістерде екі рет солай істеді. Бағасы — ол циклге де түсіп кетуі мүмкін, ал оны бірдеңе тоқтатуға тиіс.

Егер тапсырма әрқашан сол үш қадамды қажет етсе, сол үш қадамды жазыңыз. Оқуға болатын pipeline қадағалап отыруға тура келетін agent-тен қымбат тұрады.

Тәжірибе · Механизм

Жиырма жолдағы цикл

Бұл қалтада фреймворк жоқ, әрі қажет те емес. Agent — 9-дәрістен таныс чат шақыруының айналасындағы while циклі. 

messages = [{"role": "system", "content": SYSTEM},
            {"role": "user",   "content": question}]

for step in range(MAX_STEPS):
    response = client.chat.completions.create(
        model=model,
        messages=messages,
        tools=tools.openai_tools(),     # the schemas, sent every turn
        tool_choice="auto",             # the model decides whether to call one
    )
    message = response.choices[0].message
    messages.append(message)            # the assistant turn, verbatim

    if not message.tool_calls:          # plain text = it is finished
        return message.content

    for call in message.tool_calls:     # it may ask for several at once
        result = tools.call(call.function.name,
                            json.loads(call.function.arguments))
        messages.append({"role": "tool",
                         "tool_call_id": call.id,
                         "content": json.dumps(result)})
Мұнда маңызды бес нәрсе
tools=
JSON схемалары тек біріншісіне емес, әр сұранысқа кіреді. Модельдің шақырулар арасында жады жоқ; әр ходта оған не істей алатыны қайтадан айтылады.
tool_choice="auto"
Модель tool шақыруы да, бірден жауап беруі де мүмкін. "required" арқылы мәжбүрлеу кейде пайдалы, әдетте тапсырманың шын мәнінде pipeline екенінің белгісі.
assistant ходын сөзбе-сөз қосу
Оның tool_calls бөлігімен қоса. Әр құрал жауабы шақыруға tool_call_id арқылы сәйкестендіріледі, ал олар сәйкес келмесе API келесі сұранысты қабылдамайды.
tool_calls жоқ — демек бітті
Тоқтау шарты осы ғана. Модель аяқтағанын жай ғана мәтінмен жауап беру арқылы білдіреді.
range(MAX_STEPS)
Мұндағы while True — жоғарғы шегі жоқ шот. Бізде ол 8.

Тәжірибе · Tools

Tool үш нәрседен тұрады

Функция, схема және сөйлем. Студенттер біріншісін жазады, екіншісіне шыдайды, үшіншісін өткізіп жібереді — ал agent жұмыс істей ме дегенді дәл үшіншісі шешеді. 

"geocode": {
    "fn": geocode,
    "schema": {
        "name": "geocode",
        "description": "Look up a place: coordinates, country, population, "
                       "elevation and timezone. Use this whenever you need "
                       "facts about a city rather than guessing them.",
        "parameters": {
            "type": "object",
            "properties": {
                "place":   {"type": "string", "description": "City or town name, e.g. Shymkent"},
                "country": {"type": "string", "description": "Optional ISO country code, e.g. KZ"},
            },
            "required": ["place"],
        },
    },
},

Алты құрал

Agent — Қазақстан бойынша ештеңе білмейтін саяхат көмекшісі. Оның жауабындағы әр факт сіздің көз алдыңызда алынады. Agent деген осы, әрі бұл дәріс Қазақстан туралы дереккөзін көрсете алмайтын ештеңе айтпайтынын білдіреді.

Нәтиже · Ұстамдылық

Ең арзан дұрыс жауап құралсыз болады

Q: What will the weather be in Astana on 1 March next year?

ANSWER
I can only provide weather forecasts for up to 16 days in advance.
Unfortunately, I cannot give you the weather for March 1st of next year.

0 tool calls, 572 prompt tokens, 52 output tokens, 2.4 s

System prompt болжам шамамен екі аптаға ғана жететінін және мұны ойдан шығармай айту керегін жазады. Солай болды да, бірде-бір шақырусыз. Әрекет етпеуді білу — қабілет, әрі agent демонстрациялары ешқашан көрсетпейтіні дәл осы: 572 tokens, ал бұл беттегі ең қымбат жүгіріс 6 451.

Ол не істемегенін де байқаңыз: ол weather_forecast-ты ойдан шығарылған күнмен шақырып, қайтқанын қайталап айтпады. Мағынасыз шақырылған құрал әдетте бірдеңе қайтарады, ал «бірдеңе» — еркін сөйлейтін модельге сенімді әрі қате жауап құру үшін керегінің дәл өзі.

Шамамен қадам × орташа тарих, әрі орташа тарихтың өзі қадаммен бірге өседі. Қадамды екі есе көбейту шотты екі еседен артық өсіреді: 2 ход 1 574 тұрады, 7 ход — 6 451, яғни 3.5× ход 4.1× tokens береді.
құрал схемалары да әр ходта
Біздің алты схема шамамен 500 tokens, ең ауыр жүгірістің жеті ходының бәрінде қайта жіберіледі. Жиырма құрал әңгіменің өзінен қымбат тұрар еді.
ақау екі рет төленеді
Сәтсіз шақыру бір ходқа тұрады, содан соң оның қате туралы хабарламасы тарихта жатып, жүгіріс соңына дейін қайта жіберіледі.

8-дәріс tokens саны мен жарияланған тарифтен шотты қалай есептеуді көрсетті; арифметика сол күйі. Өзгеретіні — tokens санын енді сұраққа қарап болжай алмайсыз, өйткені ход санын модель шешеді.

Ол елемеген нұсқау

System prompt-та мынадай жол бар, рухы жағынан бас әріппен: «Әр қосынды, жиынтық немесе күндік шама үшін calculate қолдан. Ойша есептеме.» 

Q: I have 500 USD for three days in Shymkent. What is that per day in tenge?

[1] convert_currency(amount=500, from_currency='USD', to_currency='KZT')
    -> {"converted": 222439.02, "rate": 444.878043, "rate_date": "Thu, 24 Sep 2026 ..."}
[2] calculate(expression='500/3')
    -> {"result": 166.666667}

ANSWER
500 USD is approximately 222,439.02 KZT at the exchange rate of 444.88 KZT per USD
on September 24, 2026.

For three days, that amounts to about 166.67 USD per day, which is approximately
74,146.34 KZT per day.

Бөлулерді санаңыз. Ол 500/3 үшін calculate шақырды, содан соң 74 146.34 шығарды — бұл 222439.02 / 3 — ештеңе шақырмай. Екінші бөлуді ол өз нұсқауына тікелей қайшы, ойша жасады.

Әрі жауап дұрыс. 222 439.02 ÷ 3 = 74 146.34 дәл солай. Бөлімнің жазылу себебі де осы: ақау шығыста көрінбейді. Оны тек trace-тен және тек санасаң ғана көресің. Нұсқауларын 90% жағдайда орындайтын agent әрқашан орындайтынмен бірдей көрінеді — қалған 10% маңызды жерге түскенше.

Онымен шын мәнінде не істер едіңіз
өлшеу
Жиырма ақша сұрағын жүгіртіп, қаншауы сәйкес calculate шақыруынсыз санға келетінін санаңыз. Тағы да 9-дәрістің ережесі: prompt туралы өлшенбеген тұжырым — пікір.
құралды жалғыз жол ету
convert_currency құралына divide_by аргументін беріңіз, сонда күндік шама сол саны бар құралдан қайтады. «Ол құралды қолданбады» дегеннің ең жақсы емі әдетте жақсырақ құрал.
кейін кодта тексеру
Соңғы жауаптан сандарды алып, әрқайсысы қандай да бір құрал нәтижесінде кездесетінін тексеріңіз. Он жол, әрі дәл осы жағдайды ұстайды.
prompt-та жай айқайламау
Бас әріппен «ӘРҚАШАН құралды қолдан» — бірінші рефлекс және төртеуінің ең әлсізі.

Теория · Пайымдау

Оны қашан құрмау керек

Agents — қазіргі саладағы ең артық қолданылатын идея. Тексеру қарапайым: қадам саны кіріс деректерге шынымен тәуелді ме?

Pipeline жазыңыз

Бұл пікірлерді классификациялау. Бұл құжатты қысқарту. Бұл бетті аудару. Осы бес үзінді бойынша жауап беру. Қадамдар әрқашан бірдей, ендеше соларды жазыңыз: құны төмен, latency тұрақты, әрі кәдімгі тестпен тексерілетін бағдарлама аласыз.

Agent жазыңыз

Не керек болатынын алдын ала білу мүмкін емес сұрақтар: бір іздеу ме, алты ма, бұл құрал ма, анау ма, қазір тоқтау ма, жалғастыру ма. Бюджет туралы сұрағымызға жеті шақыру керек болды; болжам сұрағына бірде-бірі. Екеуін де қамтитын pipeline жоқ.

Циклді таңдап нені қиясыз
болжамды құнды
Осы бетте өлшенген: пайдаланушы бірдей қарапайым деп санайтын сұрақтарға 572-ден 6 451 prompt tokens-ке дейін. 11× шашырау.
болжамды кідірісті
2.4 с-тан 17.2 с-қа дейін. Адам күтіп тұрса, сол ауқым өнімнің өзі.
қайталанымдылықты
Сол сұрақ басқа күні басқа жолмен жүруі мүмкін. Temperature-ді төмен бекітіңіз, әр trace-ті логтаңыз және жүгіріс дәлел емес, айғақ екенін қабылдаңыз.
оңай тестілеуді
Бір шығысты assert-пен тексеру енді мүмкін емес. Құралдар бөлек тестіленеді, ал цикл сценарийлі модельге қарсы — жоғарыдағы алты ақау түрі дәл осылай, бір тиын жұмсамай тексерілген.

Пайдалы рет: prompt, содан соң retrieval, содан соң agent, содан соң fine-tuning. Бұл 9-дәрістің реті, тағы бір басқышпен, әрі басқыш сайын қымбаттайды.

Сұраңыз

Қазақша, орысша немесе ағылшынша. Құрал нәтижелері қай тілде келсе де, agent сұрақтың тілінде жауап береді.

Қараңыз

Әр құрал шақыруы аргументтерімен және нәтижесімен, сәтті болса жасыл, болмаса қызыл. Демонстрация кезінде осы бағанға қарау керек.

Санаңыз

Құрал шақырулары, prompt tokens, output tokens, секундтар және астында басылатын ходтар бойынша tokens өсімі. Циклдің құны нақты уақытта.

llm.py .env файлын оқып, backend таңдайды: кілт берілсе OpenAI, әйтпесе 9-дәрістің жергілікті llama-server-і. Agent коды өзіне қайсысы тигенін ешқашан білмейді — «agent деген цикл, өнім емес» дегеннің практикалық мәні осы.

Аудиторияда

Білімді тексеру

Аяқтамас бұрын бірге жауап беретін сегіз сұрақ.

1-сұрақ

Әріптесіңіз өзінің RAG жүйесін «agent» дейді, өйткені онда төрт қадам бар. Ол дұрыс айта ма?

Жауапты көрсету

Жоқ. Қадам — шешім емес. Егер әр сұрақ сол төрт қадаммен жүрсе, жолды бағдарламашы таңдаған, демек бұл pipeline. Тексеру — қадам саны кіріске қарай өзгере ме: бізде бес сұраққа 0, 2, 4, 5 және 7 шақыру болды.

2-сұрақ

Цикл agent-тің бітіргенін қайдан біледі?

Жауапты көрсету

Модель мәтінмен және tool_calls-сыз жауап береді. Тоқтау шарты осы ғана — арнайы «дайын» сигналы жоқ. Сондықтан да қадам шегі керек: модельдің тоқтауды таңдайтынына ешнәрсе кепілдік бермейді.

3-сұрақ

Бір жүгіріс 4 шақыру жасап 2 052 prompt tokens тұрды. Екіншісі 5 шақыру жасап 4 751. Неге бір артық шақыру екі еседен қымбат?

Жауапты көрсету

Өйткені шақырулар емес, ходтар төленеді. 4 шақырулық жүгіріс төртеуін бірден сұрады, сондықтан ход екеу болды. 5 шақырулық жүгіріс оларды тізбектеді, сондықтан ход бесеу болды, ал әр ход бүкіл тарихты және алты құрал схемасын қайта жібереді. Тәуелсіз іздеулерді топтаңыз; тізбекті екінші қадамға біріншінің нәтижесі керек болғанда ғана құрыңыз.

4-сұрақ

Құрал {"error": ...} қайтарудың орнына Python ерекшелігін тастайды. Не бұзылады?

Жауапты көрсету

Цикл өледі, оған дейін жұмсалған барлық tokens босқа кетеді, пайдаланушы stack trace көреді, ал модель қалпына келу мүмкіндігінен айырылады. Шарын жүгірісі — қарама-қарсы мысал: қате дерек болып келді, модель ондағы нұсқауды оқыды, латыншаға көшті де аяқтады.

5-сұрақ

Agent-ке әр қосынды үшін calculate қолдану айтылған еді. Ол 222 439.02-ні 3-ке ойша бөліп, дұрыс жауап алды. Мұнда мәселе бар ма?

Жауапты көрсету

Иә, әрі жауаптың дұрыс болуы — дәл сол мәселе. Нұсқау үнсіз бұзылды; шығыста бұл көрінбейді. Келесі жолы сан күрделірек болады да, жауап дәл сол сенімді үнмен қате болады. Жақсырақ құралмен (айырбастау divide_by қабылдасын) немесе жауаптағы әр сан қандай да бір құрал нәтижесінде бар ма деп кодта тексерумен түзетіңіз.

6-сұрақ

calculate неге eval емес, AST аралаумен жазылған?

Жауапты көрсету

Өйткені өрнекті модель жазады, ал модель Wikipedia мен ашық API-лардан мәтін оқиды. Бұл — сіздің процесіңізде аяқталатын сенімсіз тізбек. __import__('os').system('echo pwned') орындауды сұрағанда құрал only + - * / // % ** and numbers are allowed деп жауап береді. eval-мен ол мұны орындар еді.

7-сұрақ

Agent келесі жылғы наурыздағы ауа райы туралы сұраққа бірде-бір құрал шақырмай жауап берді. Бұл сәтсіздік пе?

Жауапты көрсету

Жоқ — бұл беттегі ең жақсы жүгіріс. System prompt болжам шамамен екі аптаға жететінін және мұны ойдан шығармай айту керегін жазған, солай болды да, 572 tokens және 2.4 с. Қорқатыны — керісінші: құралды мағынасыз күнмен шақырып, бірдеңе алып, оны сеніммен қайталап айту.

8-сұрақ

Agent қазақ қала атауларында үнемі сүрінді. Мұнда жақсырақ prompt көмектесер ме еді?

Жауапты көрсету

Жоқ. geocode анықтамалықтан тек ағылшынша іздеді, сондықтан «Алматы» құрал үшін тура мағынасында жоқ еді, әрі сегіз қадамның төртеуі сәтсіз іздеуге кетті. Түзету құралда болды: ағылшын, орыс және қазақ тілдерін, содан соң транслитерацияны көру. Trace нашар көрінгенде, әуелі модель нашар пайымдады ма әлде құрал нашар жауап берді ме, соны шешіңіз.

Тәжірибе

Практикалық тапсырмалар

code_files/lesson10/ ішінде жұмыс істеңіз. Мұндағының бәрі — бір команда немесе бір шағын түзету.

1-тапсырма — Кестені қайталаңыз

python3 agent.py --demo жүгіртіп, өз шақыру сандарыңыз бен tokens жиынын жоғарыдағы кестемен салыстырыңыз. Олар дәл сәйкес келмейді. Бұл неге баг емес, күтілетін нәрсе екенін бір сөйлеммен жазыңыз.

2-тапсырма — Сипаттаманы бұзыңыз

tools.py ішінде geocode сипаттамасын жай ғана «Looks up a place.» деп өзгертіңіз. Халық саны керек үш сұрақ қойыңыз. Ол әлі де құралды шақыра ма, әлде болжай бастай ма? Сіз сипаттаманың неге тұратынын өлшеп шықтыңыз.

3-тапсырма — Арифметиканы мәжбүрлеңіз

convert_currency құралына divide_by аргументін қосып, күндік шама құралдан қайтатын етіңіз. 500 USD сұрағын қайта жүгіртіңіз. Дереккөзсіз бөлу жоғала ма?

4-тапсырма — Шекті төмендетіңіз

--max-steps 2 қойып, жеті қадам керек болған Түркістан бюджеті сұрағын қойыңыз. Не қайтатынын оқыңыз. Содан соң шекке жеткенде нағыз өнім не істеуі керегін шешіңіз: кешірім сұрау, ішінара жауап беру немесе эскалациялау?

5-тапсырма — Құрал қосыңыз

geocode әлдеқашан қайтаратын уақыт белдеуін пайдаланып timezone_difference(place_a, place_b) жазыңыз. Тіркеңіз де, agent оны айтқызбай-ақ таңдайтын сұрақ табыңыз.

6-тапсырма — Дереккөздерді тексеріңіз

Соңғы жауаптан әр санды алып, ол сол жүгірістің құрал нәтижелерінде кездесетінін тексеретін скрипт жазыңыз. Жеті демо-сұраққа жүгіртіңіз. Осы беттегіден басқа қанша дереккөзсіз сан табасыз?

7-тапсырма — Екі backend

Бір сұрақты OpenAI арқылы және 9-дәрістің жергілікті 4 B моделі арқылы жүгіртіңіз. Құрал таңдауын, қадам санын және жалпы tokens-ті салыстырыңыз. «Агенттіктің» қай бөліктері кішірек модельде де сақталады?

8-тапсырма — Өтірік айтатын құрал

convert_currency бағамды он есе үлкен қайтаратын етіңіз. Бюджет туралы сұрақ қойыңыз. Agent бірдеңе дұрыс емес екенін байқай ма? Бұл құрал шығысына сену туралы нені білдіретінін екі сөйлеммен жазыңыз.

Қорытынды

Бүгін біз үйрендік

  • Agent — модель келесі әрекетті өзі таңдайтын цикл; тек қадамдар pipeline-ды agent-ке айналдырмайды
  • Цикл шамамен жиырма жол: құралдармен сұра, сұралғанын орында, нәтижелерін қос, қайта сұра
  • Ол модель мәтінмен әрі tool calls-сыз жауап бергенде тоқтайды — сондықтан қадам шегі міндетті
  • Tool — функция, JSON схемасы және сипаттама; сипаттама prompt болып табылады және құралдың мүлдем қолданылатынын шешеді
  • Біздің agent Қазақстан туралы ештеңе білмейді: әр қашықтық, болжам, бағам және сипаттама орындалу кезінде алынды
  • Сол agent бес қарапайым сұраққа 0, 2, 4, 5 және 7 шақыру жасады — жолды сұраққа қарап болжай алмайсыз
  • Шақыру емес, ход төленеді: 2 ходтағы 4 шақыру 2 052 tokens тұрды; 5 ходтағы 5 шақыру — 4 751
  • Құн жеті сұрақта 572-ден 6 451 prompt tokens-ке дейін өсті, 11× шашырау, ал кідіріс 2.4 с-тан 17.2 с-қа дейін
  • Қателер ерекшелік емес, дерек болуға тиіс — agent-тің сәтсіз іздеуден кейін қалпына келуіне дәл осы мүмкіндік берді
  • Қате туралы хабарламаны модельге арнап жазыңыз: «латынша жазуды көріңіз» дегеннің өзі қалпына келуді туғызды
  • Agents сәтсіз шақыруларды қайталайды: біздікі өз тарихында әлі көріп тұрған бірдей құлайтын шақыруды қайта жіберді
  • Модель шығысына ешқашан eval жоқ; calculate __import__('os').system(...) дегеннен бас тартты
  • Ол calculate қолдану туралы өз нұсқауын бұзып, бәрібір дұрыс жауап алды — бұл тек trace-те көрінеді
  • Беттегі ең жақсы жүгіріс бірде-бір құрал шақырмады, өйткені адал жауап «мен мұны біле алмаймын» еді
  • Нашар trace модельдің емес, құралдың кінәсі болды: қазақ атауларын түзету қадам санын екі есе азайтты
  • Prompt, содан соң retrieval, содан соң agent, содан соң fine-tuning — дәл осы ретпен, өйткені әр басқыш қымбаттау
