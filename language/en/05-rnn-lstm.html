Theory · The problem

What every model so far has thrown away

Bag of Words counted. TF-IDF weighted the counts. Lecture 4 averaged word vectors. All three are functions of which words appeared, never of where. 

import re
from collections import Counter

import numpy as np
from gensim.models import Word2Vec

word2vec = Word2Vec.load("models/word2vec.model")

a = "қосымша өте жақсы емес"      # "the app is not very good"
b = "емес жақсы өте қосымша"      # the same four words, shuffled

def bag_of_words(text):
    return Counter(re.findall(r"\w+", text.lower()))

def document_vector(text):
    words = re.findall(r"\w+", text.lower())
    return np.mean([word2vec.wv[w] for w in words if w in word2vec.wv], axis=0)

print("«" + a + "»")
print("«" + b + "»")
print()
print("same bag of words     :", bag_of_words(a) == bag_of_words(b))
print("same TF-IDF row       :", bag_of_words(a) == bag_of_words(b), "(it is built from the counts)")
print("same document vector  :", bool(np.allclose(document_vector(a), document_vector(b))))
print("largest difference    :", float(np.abs(document_vector(a) - document_vector(b)).max()),
      "— floating-point noise, not meaning")
print()

Four words, two meanings, one input. қосымша өте жақсы емес is a complaint; shuffling the same four words is not. Every representation we have built collapses them into the same row of numbers, so no classifier trained on top could ever separate them — the information was destroyed before the classifier ran. The difference of 3 × 10⁻⁸ is the order in which the floats were summed, nothing more.

This lecture is about the fix. Instead of collapsing the review into one point, we feed the words in one at a time and let the model keep a running summary. Order is then part of the computation rather than something discarded before it starts.

Theory · The model

What a recurrent network is

One small network, applied once per word, carrying a summary of everything it has read so far.

A recurrent neural network keeps a hidden state: a vector that starts at zero and is rewritten at every word, h = f(h, word). The same f and the same weights run at every position. After the last word, that one vector is the model's summary of the review.

The same network drawn four times, not four networks. Its weights are shared across positions, so a review of three words and one of forty go through exactly the same parameters.

Because the words arrive in order, жақсы емес and емес жақсы now produce different hidden states. That is the entire reason for the extra machinery: nothing else in the course could tell those two apart.

What changed since Lecture 4
input
a sequence of word vectors instead of their average
embeddings
no longer a separate step — they became the first layer of the network, trained together with everything else
what is learned
the weights come from gradient descent on the labels, not from the distributional hypothesis
output
one hidden state that saw the words in order, then a linear layer to the classes

Reading: the embedding step did not disappear. It became layer one — and at the end of this lecture we will start it from the vectors trained in Lecture 4.

Theory · The fix

Why a plain RNN forgets, and what an LSTM does

The hidden state is rewritten at every single word. Rewrite it forty times and whatever was in it at the start is gone.

The vanishing gradient

To learn that the first word mattered, the training signal has to travel back through every step in between, and at each step it is multiplied by the same weight matrix. Multiply a number smaller than one by itself forty times and it is effectively zero; multiply one larger than one and it explodes. In practice a plain RNN learns the last few words well and the start of a long review hardly at all. The clip_grad_norm_ in our training loop is the standard patch for the exploding half; nothing patches the vanishing half.

An LSTM adds a second vector, the cell state, which travels from step to step almost untouched — added to and erased from, not rewritten. Three gates, each a small network producing numbers between 0 and 1, decide what to erase, what to add, and what to reveal.

The cell state runs straight along the top. The gates edit it; they do not replace it.

The three gates
forget
multiplies the cell state, choosing what to drop. Near 1 keeps a memory alive across many words
input
decides how much of the new candidate value to add at this step
output
decides how much of the cell state becomes the visible hidden state

Why this helps: the cell state's path from one step to the next is an addition, not a matrix multiplication, so the gradient can travel a long way back without shrinking to nothing.

The cost is size. An LSTM computes four things where an RNN computes one — the three gates and the candidate value — so its recurrent weight matrices are four times as tall. You will see that literally in the parameter list further down: (512, 100) where a plain RNN would have (128, 100).

Padding a batch

Reviews have different lengths, but a tensor is a rectangle. We pad to the longest review in the batch and pass the true lengths alongside, so the network can stop where each review actually ends.

Three reviews of length 3, 5 and 1, padded into one 3 × 5 batch. The grey cells exist only to make the rectangle.

pack_padded_sequence is what makes the padding harmless. Without it the network would read six cells of <pad> and update its hidden state on them, so a short review would end with a state built mostly from filler. Packing tells PyTorch to run 9 real steps instead of all 15 cells — correct and faster.

Practice · The model

The network in PyTorch

Three layers and eleven lines. Switching between an RNN and an LSTM is one word. 

import torch
import torch.nn as nn

PAD = 0

class Recurrent(nn.Module):
    """Embedding -> RNN or LSTM -> Linear."""

    def __init__(self, vocab_size, classes, kind="lstm", dim=100, hidden=128, dropout=0.3):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, dim, padding_idx=PAD)
        cell = nn.LSTM if kind == "lstm" else nn.RNN
        self.rnn = cell(dim, hidden, batch_first=True)
        self.dropout = nn.Dropout(dropout)
        self.out = nn.Linear(hidden, classes)

    def forward(self, ids, lengths):
        embedded = self.dropout(self.embedding(ids))          # (batch, words, dim)
        packed = nn.utils.rnn.pack_padded_sequence(
            embedded, lengths, batch_first=True, enforce_sorted=False)
        _, state = self.rnn(packed)
        hidden = state[0] if isinstance(state, tuple) else state   # LSTM returns (h, c)
        return self.out(self.dropout(hidden[-1]))             # (batch, classes)


torch.manual_seed(42)
model = Recurrent(vocab_size=5916, classes=2, kind="lstm")   # the vocabulary above

Reading the parameter list
embedding.weight
(5916, 100) — one row per vocabulary entry. 83% of all parameters are here
rnn.weight_ih_l0
(512, 100) — input to hidden. 512 is 4 × 128: the LSTM's three gates and its candidate value, stacked
rnn.weight_hh_l0
(512, 128) — hidden to hidden, the recurrent part, applied once per word
out.weight
(2, 128) — 256 numbers turn the final hidden state into two class scores

Reading: almost the entire model is the embedding table. The recurrent machinery everyone talks about is 117 760 numbers out of 709 618.

Three details in forward. state[0] if isinstance(state, tuple) is there because an LSTM returns (hidden, cell) and an RNN returns just the hidden state. hidden[-1] takes the last layer's state. And dropout appears twice — on the embeddings and before the classifier — because with 700 000 parameters and 8 000 examples, this model can memorise the training set.

Practice · Training

The training loop, and the first result

Five lines repeated for every batch: zero the gradients, run forward, measure the loss, run backward, take a step. 

import os
import re
import time

from dotenv import load_dotenv

load_dotenv(".env")

import pandas as pd
import torch
import torch.nn as nn
from datasets import load_dataset
from torch.utils.data import DataLoader

PAD, UNK, SEED = 0, 1, 42

# ---- data ----------------------------------------------------------------
def split(name, per_class):
    df = load_dataset("issai/kazsandra", "polarity_classification", split=name,
                      token=os.getenv("HF_TOKEN")).to_pandas()
    df = pd.concat([g.sample(per_class, random_state=SEED) for _, g in df.groupby("label")])
    return df.sample(frac=1, random_state=SEED).reset_index(drop=True)

def tokenize(text):
    return re.findall(r"\w+", str(text).lower())

train_df, test_df = split("train", 4000), split("test", 1000)

counts = {}
for text in train_df["text_cleaned"]:
    for word in tokenize(text):
        counts[word] = counts.get(word, 0) + 1
vocab = {"<pad>": PAD, "<unk>": UNK}
for word in sorted((w for w, c in counts.items() if c >= 2), key=lambda w: (-counts[w], w)):
    vocab[word] = len(vocab)

def encode(df, max_len=60):
    rows = []
    for text, label in zip(df["text_cleaned"], df["label"]):
        ids = [vocab.get(w, UNK) for w in tokenize(text)][:max_len]
        rows.append((ids or [UNK], int(label)))
    return rows

def collate(batch):
    lengths = torch.tensor([len(ids) for ids, _ in batch])
    padded = torch.full((len(batch), int(lengths.max())), PAD, dtype=torch.long)
    for i, (ids, _) in enumerate(batch):
        padded[i, :len(ids)] = torch.tensor(ids)
    return padded, lengths, torch.tensor([y for _, y in batch])

train_rows, test_rows = encode(train_df), encode(test_df)
test_batches = DataLoader(test_rows, 64, shuffle=False, collate_fn=collate)

def shuffled_batches():
    """A fresh generator each time, so every model sees the same batch order."""
    return DataLoader(train_rows, 64, shuffle=True, collate_fn=collate,
                      generator=torch.Generator().manual_seed(SEED))

# ---- model ---------------------------------------------------------------
class Recurrent(nn.Module):
    def __init__(self, vocab_size, classes, kind, dim=100, hidden=128, dropout=0.3):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, dim, padding_idx=PAD)
        self.rnn = (nn.LSTM if kind == "lstm" else nn.RNN)(dim, hidden, batch_first=True)
        self.dropout = nn.Dropout(dropout)
        self.out = nn.Linear(hidden, classes)

    def forward(self, ids, lengths):
        packed = nn.utils.rnn.pack_padded_sequence(
            self.dropout(self.embedding(ids)), lengths, batch_first=True, enforce_sorted=False)
        _, state = self.rnn(packed)
        hidden = state[0] if isinstance(state, tuple) else state
        return self.out(self.dropout(hidden[-1]))

# ---- train ---------------------------------------------------------------
def accuracy(model, batches):
    model.eval()
    right = total = 0
    with torch.no_grad():
        for ids, lengths, labels in batches:
            right += int((model(ids, lengths).argmax(1) == labels).sum())
            total += len(labels)
    return right / total

print(f"train {len(train_df)}  test {len(test_df)}  vocabulary {len(vocab)}\n")

for kind in ("rnn", "lstm"):
    torch.manual_seed(SEED)
    model = Recurrent(len(vocab), 2, kind)
    loss_fn, optimiser = nn.CrossEntropyLoss(), torch.optim.Adam(model.parameters(), lr=1e-3)
    print(f"{kind.upper()}  {sum(p.numel() for p in model.parameters()):,} parameters")
    train_batches = shuffled_batches()
    for epoch in range(1, 6):
        model.train()
        started, running = time.time(), 0.0
        for ids, lengths, labels in train_batches:
            optimiser.zero_grad()
            loss = loss_fn(model(ids, lengths), labels)
            loss.backward()
            nn.utils.clip_grad_norm_(model.parameters(), 5.0)
            optimiser.step()
            running += loss.item() * len(labels)
        print(f"  epoch {epoch}  loss={running / len(train_df):.4f}"
              f"  test={accuracy(model, test_batches):.3f}  ({time.time() - started:.0f}s)")
    print()

The five lines that do the learning
optimiser.zero_grad()
PyTorch accumulates gradients, so they must be cleared before each batch. Forgetting this is the most common beginner bug
model(ids, lengths)
the forward pass — class scores for every review in the batch
loss_fn(scores, labels)
CrossEntropyLoss takes raw scores, applies softmax itself, and gives one number to minimise
loss.backward()
the gradient of that number with respect to every parameter, computed automatically
optimiser.step()
Adam nudges each parameter in the direction that lowers the loss

And one guard: clip_grad_norm_ caps the gradient before the step. Recurrent networks are where gradients actually explode, and without it the RNN run can diverge into nan.

The LSTM is better, and both are worse than Lecture 3. The RNN reaches 0.755 and the LSTM 0.772, on the same balanced 8 000 / 2 000 split where TF-IDF with logistic regression scored 0.780 and averaged fastText vectors scored 0.792. Seven hundred thousand parameters, five epochs of training, and we are behind a linear model on bag-of-words features.

Read the loss column against the test column. The LSTM's training loss falls steadily from 0.61 to 0.41 while test accuracy stops moving after epoch 4. The model is still learning — it is just learning the training set. That is overfitting, and with 700 000 parameters and 8 000 nine-word reviews it is exactly what you should expect.
Practice · Two fixes

Making it competitive

Two changes, neither of them to the architecture. Both attack the same problem: not enough data for this many parameters.

Fix 1 — start from the Lecture 4 vectors

The embedding table is 83% of the model, and it starts as noise. But we already trained an embedding table in Lecture 4, on 134 368 reviews without using a single label. Copying it in is four lines.

Accuracy is the wrong metric for an ordered scale. It charges the same penalty for calling a five-star review four stars as for calling it one star. When classes have an order — ratings, severity levels, grades — report the distance as well: mean absolute error, or the within-one accuracy above. A model that is never more than one star off is useful; its accuracy of 0.374 makes it sound useless.

And notice what is not the explanation. The test set is balanced at 490 per class, so this is not the imbalance of the raw data showing through. Five ordered classes on nine-word reviews is simply a harder problem than two.

Theory · The honest summary

What recurrence still cannot do

It reads strictly left to right

When the model reaches емес it cannot go back and revise what it thought about жақсы. A bidirectional LSTM reads both ways and helps, but it is two passes glued together, not a solution.

Everything squeezes through one vector

A forty-word review has to fit into 128 numbers before the classifier sees anything. The longer the text, the more that bottleneck costs.

It cannot be parallelised

Step 20 needs the result of step 19. Words cannot be processed simultaneously, which is exactly why training on very large corpora became impractical.

Distance still costs

Gates slow the forgetting, they do not stop it. Linking word 2 to word 45 means carrying information through 43 updates.

  • Averaged embeddings→
  • RNN→
  • LSTM→
  • Attention

The next lecture removes the loop entirely. Instead of passing information along a chain, every word looks directly at every other word in one step — which fixes the bottleneck, the distance penalty and the parallelism problem at once. That is attention, and it is what Transformers are built from.

In class

Knowledge check

Five questions we answer together before finishing.

Question 1

What can an RNN represent that an average of word vectors cannot?

Show Answer

Order. The hidden state after жақсы емес differs from the one after емес жақсы; the average is identical for both, as measured at the top of this page.

Question 2

Why is rnn.weight_ih_l0 shaped (512, 100) when the hidden size is 128?

Show Answer

512 = 4 × 128. An LSTM computes four things at each step — the forget, input and output gates plus the candidate value — and PyTorch stacks their weight matrices into one.

Question 3

The LSTM's training loss keeps falling while test accuracy stops moving. What is happening, and what would you change?

Show Answer

Overfitting — 700 000 parameters against 8 000 short reviews. Options: stop earlier, raise dropout, shrink the model, or give it more data. We measured the last one: 40 000 reviews took it from 0.772 to 0.803.

Question 4

Why does starting from the Lecture 4 word2vec help so much in the first epoch?

Show Answer

83% of the parameters are the embedding table, and 5 743 of its 5 916 rows arrive already knowing which words behave alike. The network starts from structure instead of noise: 0.785 after one epoch against 0.727.

Question 5

The score model is 0.374 accurate. Why is that not the most informative number to report?

Show Answer

The classes are ordered, and accuracy treats every mistake as equal. The same model is within one star 70.4% of the time and off by three or more only 12.2% of the time — which is what someone deciding whether to use it actually needs to know.

Self-check quiz

Ten questions with instant feedback.

  1. What is the hidden state of an RNN?

    It starts at zero and is updated once per word by the same weights.

  2. Why can an RNN separate «жақсы емес» from «емес жақсы» when TF-IDF cannot?

    Counting and averaging are both order-blind by construction.

  3. What problem does the LSTM cell state solve?

    It moves along an addition path rather than a repeated matrix multiplication.

  4. What does the forget gate do?

    Values near 1 keep a memory alive across many words; near 0 erase it.

  5. Why does a batch need padding and lengths?

    pack_padded_sequence ran 9 real steps instead of all 15 cells.

  6. Which layer holds most of the parameters?

    Which is why initialising it well mattered more than anything else we tried.

  7. Training loss falls, test accuracy does not. This is…

    The model is still learning — the training set specifically.

  8. Starting the embedding layer from Lecture 4's word2vec helped most…

    It begins with structure instead of noise, so it needs far fewer passes.

  9. The score model scored 0.374 while guessing scores 0.200. The best way to report it is…

    On an ordered scale, how far wrong matters as much as how often.

  10. Why can a recurrent network not be parallelised across words?

    Exactly the constraint attention removes in the next lecture.
